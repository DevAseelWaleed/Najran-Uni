# تقرير التنفيذ والتحقق

الحالة: نُفّذ تطبيق كامل بواجهة وخادم وقاعدة بيانات فعلية. لم يُنشر إلى بيئة إنتاج ولم تُعتمد جاهزيته المؤسسية بعد. مصدر المشروع في هذا المجلد؛ لا يوجد مشروع سابق تم استبداله.

## الاختبارات وبيئة الجهاز

التشغيل الأول فشل بسبب مسار PostgreSQL التنفيذي العربي على Windows. المعالجة تستخدم نسخة تنفيذية في مسار مؤقت لاتيني، مع بيانات تطوير Windows في LOCALAPPDATA/FacultyPortal. قاعدة اختبار مستقلة لكل تشغيل ولا تُستخدم قاعدة الإنتاج.

Node المثبت عالميًا 20.17؛ استُخدم Node 24.19 المضمن في بيئة Codex. أوامر الجذر تختار هذا البديل على Windows إذا كان Node العالمي أقدم من 22. على خادم آخر يلزم Node 22.12+.

تنزيل Chromium تم، لكن تشغيل النسخة المنزلة أعطى spawn UNKNOWN على هذا الجهاز. تحقق التصدير واختبار المتصفح باستخدام Microsoft Edge/Chromium المثبت، مع PDF_BROWSER_CHANNEL=msedge وTEST_BROWSER_CHANNEL=msedge. على الخوادم التي تدعم Chromium، الافتراضي chromium.

حدث فشل في محدد عنصر select بسبب عدم وضوح التسمية لقارئ الشاشة. أضيف aria-labelledby وaria-describedby في عنصر الحقل المشترك، ثم نجح المسار.

نتائج الجولة النهائية: **20/20 اختبار وحدة وتكامل ناجح، و1/1 مسار متصفح ناجح**. تشمل الجولة تقييد معدل الدخول ومؤشرات اللوحة والتحقق من تحديث بياناتها بعد الحفظ. لا توجد اختبارات فاشلة في آخر جولة. مدة الاختبارات 60.83 ثانية ومدة المتصفح 49.2 ثانية متضمنة تجهيز قواعد الاختبار.

نجح بناء TypeScript للخادم وبناء Vite للواجهة. كشف npm audit ثغرات في إصدارات البداية؛ حدثت Nest إلى 12 وTailwind إلى 4 وVitest إلى 4 وNodemailer إلى 10 وRouter إلى 7. **آخر npm audit: صفر ثغرات معروفة**. لا يغني هذا عن مراجعة أمنية مؤسسية واختبار اختراق قبل الإطلاق.

## إعدادات خارجية لازمة قبل الإنتاج

- SMTP المؤسسة وتحقق وصول الرسائل الفعلي وتهيئة SPF/DKIM/DMARC.
- حساب مدير أول من متغيرات صريحة؛ لم يُنشأ حساب تجريبي في قاعدة التطوير الحالية. اختبارات الحسابات في قواعد الاختبار فقط.
- الشعار الرسمي وأسماء الكليات والأقسام المعتمدة. رفع PNG/JPEG من الإعدادات يعمل للواجهة وPDF؛ رابط HTTPS الخارجي للواجهة فقط.
- النطاق وHTTPS والـreverse proxy والاستضافة وأسرار البيئة.
- ماسح الملفات MALWARE_SCANNER إذا كانت بيئة الجامعة تدعمه، وتحديد سياسة الاحتفاظ والنسخ الاحتياطي.

## حدود حالية وأعمال تشغيلية لم تُنفذ

- لا يوجد نشر عام أو شهادة HTTPS أو تحقق بريد جامعي حي.
- لا يوجد تكامل object storage فعلي أو ماسح فيروسات مثبت؛ توجد abstraction محلية وواجهة تشغيل الماسح.
- صلاحيات المؤسسة الحالية تشمل جميع كلياتها؛ قيود قسم منفصلة أو تعدد مؤسسات غير منفذة، كما يسمح النطاق الأولي.
- تقييد المعدل محلي لكل عملية، ومناسب لنسخة خادم واحدة. التوسع متعدد النسخ يحتاج مخزنًا مشتركًا للتقييد وproxy موثوقًا.
- لا يوجد حذف نهائي للمستندات والأعضاء، ولا جدول تنظيف آلي للأسرار المنتهية؛ يتطلبان سياسة احتفاظ الجامعة.
- لم تُنفذ اختبارات ضغط على 10000 سجل أو مراجعة وصول مستقلة كاملة. حدود الرفع 10MB والاستيراد 2000 صف/80 عمودًا و50MB بعد فك الضغط والتصدير 10000 سجل.
- بعض السيناريوهات الاختيارية مثل تغيير المظهر ورفع الشعار والملفات متعددة الأوراق لم تُغطَّ باختبار متصفح مستقل؛ توجد مسارات فعلية لها، ولا تُدّعى تغطية كل حالات الإدخال.

## قائمة إكمال التشغيل المؤسسي

1. اضبط بيئة staging والبريد الحقيقي وHTTPS والتخزين والماسح.
2. نفّذ npm ci ثم generate/build/migrate وتهيئة المدير ببيانات صريحة.
3. أضف أقسام المؤسسة وشعارها دون بيانات وهمية.
4. نفّذ الاختبارات وإرسال OTP إلى بريد المؤسسة وفحص تقارير بياناتها الحقيقية.
5. اختبر النسخ الاحتياطي والاستعادة والتحميل المتوقع والصلاحيات المؤسسية.
6. اعتمد الاحتفاظ بالمستندات وتقييد المعدل في بيئة النشر ثم قرّر الإطلاق.
