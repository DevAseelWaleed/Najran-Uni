# خطة التنفيذ ومعمارية النظام

المجلد الأصلي فارغ. تطبيق مستقل بواجهة React وخادم NestJS، وقاعدة PostgreSQL بواسطة Prisma 6. الجلسات والتحديات محفوظة في القاعدة؛ ملفات خارج مجلد الويب. لا توجد بيانات أعضاء أو حسابات افتراضية. الكليات والأقسام مراجع قابلة للإدارة، والرقم الوظيفي فريد داخل الكلية. نطاق المؤسسة واحد مع علاقات كليات وأقسام قابلة للتوسع. لا يُعدّ الموقع جاهزًا للإنتاج قبل اجتياز التحقق الموثق في تقرير التسليم.

## مراحل العمل

1. المخطط، البيئة، العقود.
2. المصادقة بالبريد وكلمة المرور وOTP والجلسات والصلاحيات.
3. CRUD المستخدمين والأعضاء والمؤهلات والمرفقات.
4. الاستيراد والتصدير واللوحة والإعدادات والتدقيق.
5. الواجهة العربية والاختبارات والبناء ودليل التشغيل.

## افتراضات

- انتهاء الجلسة المطلق 8 ساعات. إنشاء الحساب يرسل رابط تهيئة كلمة المرور، دون إظهار كلمة المرور.
- حذف المستخدم تعطيل دائم قابل لإعادة التفعيل؛ أعضاء هيئة التدريس والمرفقات حذف منطقي، مع الاحتفاظ بالملفات.
- المشاهد يقرأ بيانات المؤسسة ومرفقاتها، ولا يصدّر. أدوار المؤسسة حاليًا بدون تقييد قسم منفصل.
- حدود الملفات 10MB والاستيراد 2000 صف والتصدير 10000 صف.
- البريد المحلي Mailpit حصريًا للتطوير؛ الإنتاج يحتاج SMTP حقيقيًا وHTTPS وأسرار مستقلة.
- ملفات PDF باستخدام Chromium لتشكيل العربية وخط عربي محلي.

## العقود

كل API تحت /api. POST/PATCH/DELETE تتطلب Origin مطابقًا، والعمليات المحمية تتطلب X-CSRF-Token مرتبطًا بالجلسة. cookie HttpOnly تحمل سر جلسة عشوائيًا ويُحفظ تجزئته فقط. GET /auth/me يعطي المستخدم وCSRF؛ لا تُخزن أسرار في localStorage.

تعاد الأخطاء في {message} والنتائج المرقمة في {items,total,page,pageSize}. مراجعة docs/API.md للتفاصيل.
